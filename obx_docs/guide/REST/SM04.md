# SM04 - Panduan Signature Type, Document Request, Document, Evidence & Approval Flow API

## Ringkasan Fitur

API ini dipakai admin untuk mengelola tipe approval dokumen berbasis beberapa step dan signer, mengelola document request (`dat_request`), mengelola dokumen terkelola (`dat_document`), merekam jejak evidence/approval dokumen (`dat_document_approval`), serta menjalankan flow approval melalui signature form dan flag.

## Prasyarat Akses

- Token admin aktif

## Langkah Penggunaan

1. Panggil `GET /rest/pages/SM04` untuk melihat daftar signature type.
2. Siapkan payload create atau update dengan `code`, `name`, dan `steps`.
3. Untuk setiap step, tentukan urutan `step`, `condition`, dan daftar `user_ids` signer.
4. Gunakan `GET /rest/pages/SM04/user?search=...` untuk mencari user signer aktif.
5. Simpan perubahan via `POST /rest/pages/SM04` atau `PUT /rest/pages/SM04/:id`.
6. Panggil `GET /rest/pages/SM04/request` untuk melihat daftar document request (search, sort, pagination).
7. Buat request baru via `POST /rest/pages/SM04/request` dengan `type_id`, `requester_id`, `code`, `title`; admin wajib mengirim `company_id`.
8. Perbarui field request via `PUT /rest/pages/SM04/request/:id` (status dan step tidak berubah).
9. Hapus request via `DELETE /rest/pages/SM04/request/:id`.
10. Generate signature form via `POST /rest/pages/SM04/request/:id/form` setelah request dibuat.
11. Lihat form beserta flag signer via `GET /rest/pages/SM04/request/:id/form`.
12. Tindak lanjuti approval via `PUT /rest/pages/SM04/form/:formId/flag/:flagId` dengan `status` `APPROVED` atau `REJECTED` (opsional `comment`).
13. Panggil `GET /rest/pages/SM04/document/category` untuk mendapatkan daftar kategori dokumen aktif.
14. Buat dokumen terkelola via `POST /rest/pages/SM04/document` dengan `code` dan `title`; admin wajib mengirim `company_id`.
15. Lihat daftar dokumen via `GET /rest/pages/SM04/document` (search, sort, pagination).
16. Perbarui field dokumen via `PUT /rest/pages/SM04/document/:id`; hapus via `DELETE /rest/pages/SM04/document/:id`.
17. Lihat histori revisi dokumen via `GET /rest/pages/SM04/document/:id/revision` (search, sort, pagination).
18. Tambah revisi via `POST /rest/pages/SM04/document/:id/revision` dengan `version`; admin wajib mengirim `company_id`.
19. Perbarui field revisi via `PUT /rest/pages/SM04/document/:id/revision/:revisionId`; hapus via `DELETE /rest/pages/SM04/document/:id/revision/:revisionId`.
20. Lihat jejak evidence/approval dokumen via `GET /rest/pages/SM04/document/:id/evidence` (search, sort, pagination).
21. Tambah evidence via `POST /rest/pages/SM04/document/:id/evidence` dengan `action`; admin wajib mengirim `company_id`.
22. Perbarui field evidence via `PUT /rest/pages/SM04/document/:id/evidence/:evidenceId`; hapus via `DELETE /rest/pages/SM04/document/:id/evidence/:evidenceId`.

## Validasi Hasil

- Signature type tampil kembali di list setelah disimpan.
- Approval step tersusun sesuai urutan step.
- Signer per step tersimpan dan dapat ditampilkan ulang pada detail.
- Request baru muncul di list `GET /SM04/request` dengan status `PENDING` dan `current_step` 1.
- Generate form menghasilkan satu form per step; form berisi flag untuk tiap signer dengan status `PENDING`.
- Aksi flag `REJECTED` menolak request; `APPROVED` pada semua signer (atau satu signer untuk `ANY_APPROVED`) mengunci form dan memajukan step request.
- Request yang dihapus tidak muncul lagi di list.
- Kategori dokumen aktif tampil di `GET /SM04/document/category`.
- Dokumen baru muncul di list `GET /SM04/document` dengan status `DRAFT` dan `created_by` session user.
- Dokumen yang diperbarui/hapus tercermin pada list berikutnya.
- Revisi baru muncul di list `GET /SM04/document/:id/revision` dengan status `DRAFT` dan `created_by` session user.
- Revisi yang diperbarui/hapus tercermin pada list revisi dokumen berikutnya.
- Evidence baru muncul di list `GET /SM04/document/:id/evidence` dengan `user_name` user session.
- Evidence yang diperbarui/hapus tercermin pada list evidence dokumen berikutnya.
