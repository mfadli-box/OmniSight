# SM04 - Signature Type API & Document Request API

## Ringkasan

- Route utama: `/rest/pages/SM04`
- Route signer lookup: `/rest/pages/SM04/user`
- Route document request: `/rest/pages/SM04/request`
- Route document terkelola: `/rest/pages/SM04/document` dan `/rest/pages/SM04/document/category`
- Route revision dokumen: `/rest/pages/SM04/document/:id/revision`
- Route evidence dokumen: `/rest/pages/SM04/document/:id/evidence`
- Route signature form/flag: `/rest/pages/SM04/request/:id/form` dan `/rest/pages/SM04/form/:formId/flag/:flagId`
- Tujuan: mengelola signature type untuk workflow approval dokumen (termasuk approval step dan signer per step), mengelola document request (`dat_request`), mengelola dokumen terkelola (`dat_document`) beserta histori revisinya (`dat_document_version`) dan jejak evidence/approval (`dat_document_approval`), serta menjalankan flow approval via signature form (`dat_signature_form`) dan flag (`dat_signature_flag`)
- Akses: group `admin` (`USAuth()` + `USLock()`)

## Technical Notes

- GET `/SM04` mengembalikan daftar signature type lengkap dengan nested `steps` dan `signers`
- POST `/SM04` membuat signature type baru, lalu membuat approval step dan signer terkait secara berurutan
- PUT `/SM04/:id` mengganti definisi signature type secara penuh: approval sign lama dihapus, approval step lama dihapus, lalu struktur baru ditulis ulang
- GET `/SM04/user` dipakai frontend untuk lookup signer aktif dengan filter `search`
- Query signer user memakai `company_id` dari context untuk non-admin, tetapi admin dapat melihat seluruh user aktif
- GET `/SM04/request` membaca tabel `dat_request` dengan join ke `dat_company`, `dat_signature_type`, dan `dat_user` (requester); query di-scope `company_id` untuk non-admin, admin melihat semua
- POST `/SM04/request` membuat request baru; `company_id` diambil dari context (non-admin) atau dari body (admin); default `priority` = `NORMAL`, default `status` = `PENDING`, default `current_step` = 1
- PUT `/SM04/request/:id` memperbarui field request (tidak mengubah status/step)
- DELETE `/SM04/request/:id` menghapus request
- GET `/SM04/request/:id/form` membaca daftar signature form per request, termasuk flag per form (join `dat_user` untuk `user_name`)
- POST `/SM04/request/:id/form` membuat (generate) signature form untuk tiap step approval dari signature type request; status awal `PENDING`, flag awal `PENDING`; menolak bila form sudah ada (409 `CONFLICT`)
- PUT `/SM04/form/:formId/flag/:flagId` menjalankan aksi approval satu flag (`APPROVED`/`REJECTED`); meng-update status form berdasarkan `condition` (`ALL_APPROVED`/`ANY_APPROVED`), majukan `current_step` request, atau finalisasi request (`APPROVED`/`REJECTED`) pada step terakhir
- GET `/SM04/document` membaca tabel `dat_document` dengan join ke `dat_company` dan `dat_document_category`; query di-scope `company_id` untuk non-admin, admin melihat semua
- POST `/SM04/document` membuat dokumen terkelola baru; `company_id` diambil dari context (non-admin) atau dari body (admin); `created_by` diambil dari session user; default `content_type` = `markdown`, `version` = `1.0`, `status` = `DRAFT`
- PUT `/SM04/document/:id` memperbarui field dokumen (tidak mengubah `created_by`, `approved_by`, `approved_at`)
- DELETE `/SM04/document/:id` menghapus dokumen berdasarkan id
- GET `/SM04/document/category` dipakai frontend untuk lookup kategori dokumen aktif dengan scope `company_id`
- GET `/SM04/document/:id/revision` membaca tabel `dat_document_version` milik satu dokumen (filter `document_id`); query di-scope `company_id` untuk non-admin, admin melihat semua
- POST `/SM04/document/:id/revision` menambah histori revisi dokumen; `company_id` diambil dari context (non-admin) atau dari body (admin); `created_by` diambil dari session user; default `status` = `DRAFT`
- PUT `/SM04/document/:id/revision/:revisionId` memperbarui field revisi (tidak mengubah `document_id`, `company_id`, `created_by`)
- DELETE `/SM04/document/:id/revision/:revisionId` menghapus revisi berdasarkan id
- GET `/SM04/document/:id/evidence` membaca tabel `dat_document_approval` milik satu dokumen (filter `document_id`); query di-scope `company_id` untuk non-admin, admin melihat semua; join `dat_user` untuk `user_name`
- POST `/SM04/document/:id/evidence` menambah jejak evidence/approval dokumen; `company_id` diambil dari context (non-admin) atau dari body (admin); `user_id` diisi dari session user; tabel tidak memiliki kolom `updated_at` sehingga update hanya memodifikasi field terpilih
- PUT `/SM04/document/:id/evidence/:evidenceId` memperbarui field evidence (tidak mengubah `document_id`, `company_id`, `user_id`)
- DELETE `/SM04/document/:id/evidence/:evidenceId` menghapus evidence berdasarkan id
- Write route memakai `USLogs("SM04")`

## Endpoint

- `GET /rest/pages/SM04`
	- Response: list signature type dengan field `id`, `code`, `name`, `created_at`, `steps[]`
- `POST /rest/pages/SM04`
	- Body: `code`, `name`, `steps[{ step, condition, user_ids[] }]`
- `PUT /rest/pages/SM04/:id`
	- Body: sama dengan create; bersifat overwrite untuk seluruh approval structure
- `GET /rest/pages/SM04/user?search=...`
	- Response: daftar user aktif untuk signer picker
- `GET /rest/pages/SM04/request?search=&page=&size=&sort_by=&sort_order=`
	- Response: list `dat_request` dengan join `company_name`, `type_name`, `requester_name`, plus `meta` grid (total, page, size, total_pages)
	- Field item: `id`, `company_id`, `company_name`, `type_id`, `type_name`, `requester_id`, `requester_name`, `code`, `title`, `description`, `priority`, `status`, `current_step`, `completion_note`, `completed_by`, `completed_at`, `created_at`
	- `sort_by` yang valid: `code`, `title`, `priority`, `status`, `created_at`
- `POST /rest/pages/SM04/request`
	- Body: `company_id` (wajib untuk admin), `type_id`, `requester_id`, `code`, `title`, `description` (opsional), `priority` (opsional, default `NORMAL`)
	- Priority yang dipakai: `LOW`, `NORMAL`, `HIGH`, `URGENT`
- `PUT /rest/pages/SM04/request/:id`
	- Body: `type_id`, `requester_id`, `code`, `title`, `description`, `priority` — tidak mengubah `status`/`current_step`
- `DELETE /rest/pages/SM04/request/:id`
	- Menghapus request berdasarkan id
- `GET /rest/pages/SM04/request/:id/form`
	- Response: daftar signature form dengan field `id`, `step`, `request_id`, `condition`, `status`, `created_at`, dan `flags[]` (`id`, `form_id`, `user_id`, `user_name`, `status`, `comment`, `created_at`)
- `POST /rest/pages/SM04/request/:id/form`
	- Generate signature form + flag dari approval step signature type; `count` = jumlah form yang dibuat
- `PUT /rest/pages/SM04/form/:formId/flag/:flagId`
	- Body: `status` (`APPROVED` | `REJECTED`), `comment` (opsional)
	- Validasi: request belum `APPROVED`/`REJECTED`; status harus `APPROVED` atau `REJECTED`
- `GET /rest/pages/SM04/document?search=&page=&size=&sort_by=&sort_order=`
	- Response: list `dat_document` dengan join `company_name`, `category_name`, plus `meta` grid (total, page, size, total_pages)
	- Field item: `id`, `company_id`, `company_name`, `category_id`, `category_name`, `code`, `title`, `description`, `content_type`, `content`, `file_name`, `file_size`, `version`, `status`, `created_by`, `approved_by`, `approved_at`, `is_active`, `created_at`
	- `sort_by` yang valid: `code`, `title`, `status`, `category_name`, `created_at`
- `POST /rest/pages/SM04/document`
	- Body: `company_id` (wajib untuk admin), `category_id`, `code`, `title`, `description`, `content_type` (opsional, default `markdown`), `content`, `file_name`, `file_size`, `version` (opsional, default `1.0`), `status` (opsional, default `DRAFT`)
	- `created_by` diisi otomatis dari session user
- `PUT /rest/pages/SM04/document/:id`
	- Body: `category_id`, `code`, `title`, `description`, `content_type`, `content`, `file_name`, `file_size`, `version`, `status` — tidak mengubah `created_by`/`approved_by`/`approved_at`
- `DELETE /rest/pages/SM04/document/:id`
	- Menghapus dokumen berdasarkan id
- `GET /rest/pages/SM04/document/category`
	- Response: daftar kategori dokumen aktif (`id`, `name`) untuk picker
- `GET /rest/pages/SM04/document/:id/revision?search=&page=&size=&sort_by=&sort_order=`
	- Response: list `dat_document_version` milik dokumen `:id`, plus `meta` grid (total, page, size, total_pages)
	- Field item: `id`, `document_id`, `version`, `content`, `file_path`, `status`, `note`, `created_by`, `created_at`
	- `sort_by` yang valid: `version`, `status`, `created_at`
- `POST /rest/pages/SM04/document/:id/revision`
	- Body: `company_id` (wajib untuk admin), `version` (wajib), `content`, `file_path`, `status` (opsional, default `DRAFT`), `note`
	- `created_by` diisi otomatis dari session user
- `PUT /rest/pages/SM04/document/:id/revision/:revisionId`
	- Body: `version`, `content`, `file_path`, `status`, `note` — tidak mengubah `document_id`/`company_id`/`created_by`
- `DELETE /rest/pages/SM04/document/:id/revision/:revisionId`
	- Menghapus revisi berdasarkan id
- `GET /rest/pages/SM04/document/:id/evidence?search=&page=&size=&sort_by=&sort_order=`
	- Response: list `dat_document_approval` milik dokumen `:id`, plus `meta` grid (total, page, size, total_pages)
	- Field item: `id`, `document_id`, `action`, `note`, `user_id`, `user_name`, `created_at`
	- `sort_by` yang valid: `action`, `user_name`, `created_at`
- `POST /rest/pages/SM04/document/:id/evidence`
	- Body: `company_id` (wajib untuk admin), `action` (wajib), `note` (opsional)
	- `user_id` diisi otomatis dari session user
- `PUT /rest/pages/SM04/document/:id/evidence/:evidenceId`
	- Body: `action`, `note` — tidak mengubah `document_id`/`company_id`/`user_id`
- `DELETE /rest/pages/SM04/document/:id/evidence/:evidenceId`
	- Menghapus evidence berdasarkan id

## Validasi dan Constraint

- `code` wajib diisi
- `name` wajib diisi
- Minimal ada satu approval step
- Setiap step minimal memiliki satu signer pada validasi frontend
- Nilai `condition` yang dipakai saat ini: `ALL_APPROVED` dan `ANY_APPROVED`
- Create/update request: `type_id`, `requester_id`, `code`, `title` wajib diisi
- Create request untuk admin: `company_id` wajib ada di body
- `description` dan `completion_note` disimpan sebagai string (kolom NOT NULL, gunakan string kosong jika tidak ada)
- `status` bertipe enum `approval_info` (`PENDING`, `IN_PROGRESS`, `APPROVED`, `REJECTED`, `COMPLETED`)
- Generate form hanya boleh sekali per request (`@@unique([request_id, step])` di `dat_signature_form`)
- Satu user hanya punya satu flag per form (`@@unique([form_id, user_id])` di `dat_signature_flag`)
- Create/update document: `code` dan `title` wajib diisi
- `code` dokumen unik per company (`@@unique([company_id, code])` di `dat_document`)
- `category_id` bersifat opsional (nullable, `ON DELETE SET NULL`)
- `status` dokumen memakai string bebas, default `DRAFT` (nilai umum: `DRAFT`, `IN_REVIEW`, `APPROVED`, `PUBLISHED`, `ARCHIVED`)
- `file_size` bertipe `BigInt` (int8) dan dikirim sebagai 0/nil saat tidak ada file
- Create/update revision: `version` wajib diisi
- `version` revisi unik per dokumen (`@@unique([document_id, version])` di `dat_document_version`)
- `status` revisi memakai string bebas, default `DRAFT` (nilai umum: `DRAFT`, `IN_REVIEW`, `APPROVED`, `PUBLISHED`)
- `content` dan `note` disimpan nullable (gunakan `NULL` saat tidak ada)
- Create/update evidence: `action` wajib diisi
- `action` evidence memakai string bebas (nilai umum: `SUBMIT`, `APPROVE`, `REJECT`, `PUBLISH`, `ARCHIVE`)
- `note` disimpan nullable (gunakan `NULL` saat tidak ada)
